# Flujo de git y pull requests — FrankenForms

## 1. Autoría

Todos los commits y PRs quedan **únicamente** a nombre de la cuenta configurada en git (`git config user.name` / `git config user.email`) y del usuario autenticado en `gh`.

**PROHIBIDO:**
- Agregar trailers `Co-authored-by:` o `Signed-off-by:` de un agente.
- Incluir "Generated by", menciones a Kiro, IA o asistentes en mensajes de commit, títulos o descripciones de PR.
- Modificar `git config` de ninguna forma.

## 2. Inicio de tarea

Siempre partir desde `main` actualizado:

```bash
git switch main && git pull --ff-only
git switch -c <tipo>/NN-slug
```

- `NN` = número de la tarea del spec (01, 02, …).
- `<tipo>` = `feat`, `fix`, `chore`, `docs` o `style`.
- `slug` = descripción corta en kebab-case.

Ejemplo: `feat/03-bedrock-integration`, `chore/01-scaffolding`.

## 3. Durante la tarea

Commits pequeños, uno por sub-paso lógico:

- Formato convencional en **español**, en minúsculas, sin punto final.
- Prefijos: `feat:`, `fix:`, `chore:`, `docs:`, `style:`, `test:`.
- Máximo **72 caracteres** en el título del commit.
- Nunca `git add .` sin revisar el diff primero; usar `git add <archivos>`.

## 4. Cierre de tarea

### 4a. Verificación

Si existe `package.json`:

```bash
npm run lint   # debe pasar sin errores
npm run build  # debe compilar sin errores
```

Si todavía no existe `package.json`, omitir este paso.

### 4b. Push y apertura de PR

```bash
git push -u origin HEAD

gh pr create \
  --base main \
  --title "<tipo>: <resumen en ≤70 caracteres>" \
  --body "<qué cambia, tarea del spec, cómo probar>"
```

### 4c. Merge automático

```bash
gh pr merge --auto --rebase --delete-branch
```

Si el repo no permite `--auto`:

```bash
gh pr checks --watch
gh pr merge --rebase --delete-branch
```

## 5. Después del merge

```bash
git switch main && git pull --ff-only
```

## 6. Si un check falla

Corregir en la misma rama con un commit `fix:` y volver a hacer push. El PR existente se actualiza automáticamente.

## 7. Prohibido

- Squash de commits.
- `git push --force` a `main`.
- Commits directos a `main` (sin PR).
- Más de un PR abierto a la vez.
